* Scope

Implement canonical supplied Person records, exact name/alias lookup, content-addressed
Picture ingestion, explicit candidate photo-to-Person annotations, and synchronous Target
operations. No biometric matching, face-to-name identification, or inferred gender is
implemented. This slice does not claim those earlier requested capabilities are complete.

The service owns HTTP; generic StarIntel ingest is unchanged. CouchDB owns durable
documents and image attachments. Pykka actors own state and route typed commands.
Future modules can extend supplied Person records without replacing this boundary.

* Contract

Pin the unmodified generated Star Language 0.10.1 schema and Python types, core.star,
and release lock at upstream commit 5837e9924cf4ead99ccf085521121c7f6ad4703e.
Verify all local hashes at startup and against the upstream release lock.
Public documents use lowerCamelCase, id, schemaVersion, and typed StarReference values.
CouchDB _id/_rev/_attachments exist only in the persistence adapter.

* Execution Gate

The user instructed “Lets do face-intel”, supplied the repository URL, and directed
“just pin the spec locally? and keep working” on 2026-10-03. These authorize the
bounded foundation. The implementation is limited to this scope. Live deployment, merging,
and changing upstream Star Language artifacts are separate actions.

* Acceptance

- HTTP and Target reads run through the same Pykka actors.
- Name lookup includes normalized aliases and preserves Unicode.
- Person edits require current revisions; duplicate identical writes are idempotent.
- Picture attachments are committed atomically with canonical metadata.
- Explicit annotation links remain candidate-only and never rewrite identity.
- Queues, request bodies, image pixels, and request times have hard bounds.
- Production defaults to CouchDB; test doubles cannot be selected through environment.
- Existing RAGE checks and service regression tests pass.
