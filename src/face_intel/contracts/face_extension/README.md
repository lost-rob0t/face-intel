# FaceIntel source extension

`face-intel.star` owns `org.starintel/face-intel@1`, release `0.1.0`.
It imports the exact SHA-256 of StarIntel core `0.10.1`. Document envelopes
continue to use `schemaVersion: "0.10.1"`; the extension release version is
separate. The existing core source and generated artifacts are unchanged.

| Document dtype | Generated type | Meaning |
| --- | --- | --- |
| `face-observation` | `FaceObservation` | Supplied face-region annotation in a canonical Picture, using integer pixel coordinates |
| `candidate-person` | `CandidatePerson` | Supplied tentative Person record with explicit candidate status and annotation basis |
| `face-person-candidate` | `FacePersonCandidate` | Candidate Relation from an observation to a Person or CandidatePerson |

Both candidate types require `candidateStatus: "candidate"`. Consumers must
also require `verificationStatus: "candidate"`, preserve supplied provenance,
and prevent annotation writes from changing identity fields. The relation's
predicate is `org.starintel/face-intel@1/candidate-person-for-face`.

References use the library that owns the target document, for example
`org.starintel/core@1/picture`, `org.starintel/core@1/person`, or
`org.starintel/face-intel@1/candidate-person`. Consumers check the referenced
record's dataset and dtype, require the observation rectangle to fit inside
the Picture, and require a nonblank annotation basis of at most 2000 characters.
These relationship and image-dependent rules are runtime checks; the generated
JSON Schema validates field structure. A face ID names an observation document,
not a confirmed identity. This release specifies annotation storage; detection,
biometric matching, and automatic identification are not implemented by it.

The portable manifest exports only extension declarations. The resolved
manifest adds reachable core types for self-contained JSON Schema and bindings;
those core definitions are copied from the compiler IR without alteration.
Generated outputs cover Common Lisp, Python, TypeScript, Nim, Kotlin, Java,
Go, Rust, Emacs Lisp, and Prolog. Transport-neutral messages can be wrapped by
HTTP, RabbitMQ, or StarRouter adapters; this source does not implement brokers.

```sh
sbcl --script tools/generate-face-intel-extension.lisp
python3 tools/finalize-face-intel-extension.py
sbcl --script tools/generate-face-intel-extension.lisp --check
python3 tools/finalize-face-intel-extension.py --check
python3 tools/test-face-intel-extension.py
```

`--check` compares generated bytes and the release lock without rewriting them.
Downstream consumers pin an immutable upstream commit and verify the source,
generated schema, bindings, import digest, and core release lock before startup.
